
📖 Guía de Instalación y Configuración 
⚠️ Requisitos Previos
Antes de empezar, asegurate de tener instalados los siguientes programas en tu computadora:
Python: Versión 3.12 o superior (descargar desde python.org).
Node.js: Versión 18 o superior.

Docker y Docker Compose.

🛠️ 1. Configuración de la Base de Datos
El proyecto utiliza PostgreSQL a través de Docker. El contenedor se llamará proyecto_practicas2025.
    1-Abrí una terminal en la raíz del proyecto.

    2-Levantá la base de datos ejecutando:
        Bash
        docker-compose up -d
⚙️ 2. Configuración del Backend (Django)
Abrí una terminal y navegá a la carpeta del backend:
    1-cd Backend
    2-Instalá pipenv (si no lo tenés) y creá el entorno virtual:
        pip install pipenv
        pipenv install
    (Esto instalará las dependencias necesarias como: 
    asgiref                       
    Django                        
    django-cors-headers           
    djangorestframework           
    djangorestframework_simplejwt 
    pillow
    pip
    psycopg2-binary
    PyJWT
    python-dotenv
    sqlparse
    reportlab)
    para chequear que este todo instalado correctamente, ejecutá:
        pip list

Activá el entorno virtual:
pipenv shell


Navegá a la carpeta de la interfaz:
Bash
cd Interfaz
Variables de entorno: Creá un archivo llamado .env en esta carpeta (Backend/Interfaz/) y agregá lo siguiente:

Fragmento de código
DATABASE_URL=postgresql://usuario:password@localhost:5432/nombre_db
SECRET_KEY=tu_secret_key_aqui
Prepará la base de datos ejecutando las migraciones:
    python manage.py makemigrations
    python manage.py migrate

🎨 3. Configuración del Frontend (React & Tailwind)
Abrí una nueva terminal y navegá a la carpeta del frontend:

cd Frontend/interfaz
Instalá las dependencias de Node:

npm install
(Opcional - Solo si es la primera vez que se configura Tailwind) Instalá e inicializá Tailwind CSS:

Bash
npm install -D tailwindcss@3
npx tailwind init -p
Nota: Esto generará los archivos tailwind.config.js y postcss.config.js.

🚀 ¿Cómo arrancar el proyecto todos los días?
Para trabajar en el día a día, seguí estos 3 pasos:

Paso 1: Arrancar la Base de Datos

docker start proyecto_practicas2025
Paso 2: Arrancar el Backend
En una terminal, navegá a la carpeta Backend, activá el entorno y encendé el servidor:

pipenv shell
cd Interfaz
python manage.py runserver

Paso 3: Arrancar el Frontend
En otra terminal, navegá a la carpeta Frontend/interfaz y encendé React:

Bash
npm start
(Para detener los servidores, presioná Ctrl + C en sus respectivas terminales).

🆘 Solución a Problemas Frecuentes (Troubleshooting)
Error al crear el Superusuario (ValueError con Role)
Si intentás usar python manage.py createsuperuser y te da error porque requiere una instancia del modelo Role, seguí estos pasos para crearlo directamente desde la consola interactiva:

En la terminal del backend (Backend/Interfaz), abrí la consola de Django:

Bash
python manage.py shell
Copiá, pegá y ejecutá este código (modificá los datos a tu gusto):

Python
from api.models import Role, User

# Obtenemos el rol deseado (1=Gerente, 2=Encargado, 3=Panadero, 4=Cajero)
rol_admin = Role.objects.get(id=1) 

# Creamos el superusuario asignándole el objeto del rol
User.objects.create_superuser(
    username='AdminGeneral', 
    email='admin@churreria-demo.com.ar', 
    password='ContraseñaSegura123', 
    role=rol_admin
)
exit()
Asignar un rol a un usuario ya creado
Si creaste el superusuario pero te olvidaste de asignarle el rol, usá este código en la shell:

Python
from api.models import User, Role

superuser = User.objects.get(username='NOMBRE_DEL_USUARIO')
gerente_role = Role.objects.get(name='Gerente') 
superuser.role = gerente_role
superuser.save()

# Para verificar que funcionó:
print(superuser.username, superuser.role)
Comandos Útiles de Docker:

Ver logs (errores de la BD): docker-compose logs

Apagar y destruir el contenedor: docker-compose down

Si al ejecutar python manage.py migrate el proyecto no puede arrancar porque tira un error del tipo psycopg2.errors.DuplicateColumn (indicando que una columna ya existe en la base de datos), significa que el historial está desincronizado.

Para forzar a Django a omitir esa migración y continuar con las demás, ejecutá una "migración falsa" (fake migration) indicando el nombre de la app y el número de migración problemático. Ejemplo:

Bash
# Formato: python manage.py migrate <nombre_app> <nro_migracion> --fake
python manage.py migrate api 0023 --fake
Una vez ejecutado, corré el comando de migración normal para aplicar las que falten:

Bash
python manage.py migrate
